NOTAS DOCENTE - DOS GUÍAS, UNA APLICACIÓN

VERSIÓN 1.1 - COLORES CLAROS
Fondos claros, campos blancos con borde visible, texto oscuro y botones azul claro.
Cada campo tiene una etiqueta fija encima, además de una indicación de ejemplo.
Para ver los cambios en MEmu, ejecutar de nuevo con Run en Android Studio o
instalar el APK actualizado de output\NotasDocente.apk encima del anterior.

Qué integra
1. Registro e inicio de sesión mediante HTTP, PHP y MySQL.
2. Menú principal que abre Universidades o Usuarios y mi perfil.
3. CRUD completo de universidades en SQLite: crear, buscar por ID, modificar,
   eliminar con confirmación y listar. Los datos sobreviven al cierre de la app.
4. Directorio de usuarios y modificación/eliminación de la propia cuenta.
5. Cierre de sesión y validaciones de formularios.

Las universidades son datos locales compartidos en este dispositivo, como en la
primera guía. Los usuarios están en MySQL, como en la guía HTTP. Esta integración
no sincroniza universidades con MySQL. Programas, Alumnos, Asignaturas y
Calificaciones tienen tablas base; sus pantallas corresponden a las siguientes
guías y no están implementadas en este taller.

ABRIR EL PROYECTO
Android Studio > Open > seleccionar la carpeta Taller Android 2.
Esperar a que Gradle termine de sincronizar. El lenguaje es Java y las pantallas
son archivos XML. Elegir el módulo app y pulsar Run con un emulador o teléfono.
Se incluye gradlew.bat y el wrapper para compilar también desde la terminal.
JDK: el incluido en Android Studio. SDK instalado en esta computadora: 37.0.
AGP 9.0.0 muestra una advertencia porque fue probado hasta SDK 36.1; la compilación
se verificó con el SDK 37.0 instalado. No se requiere Kotlin ni librerías JAR.

INICIAR EL SERVIDOR
En PowerShell, dentro de esta carpeta:
  powershell -ExecutionPolicy Bypass -File .\iniciar-servidor.ps1
El script usa XAMPP en C:\xampp, copia el servicio a htdocs\taller_android,
crea la base taller_android si no existe e inicia Apache y MySQL si están apagados.
Está preparado para MySQL local con root sin contraseña. No cambia otras bases.
Para otra instalación, importar servidor\base_datos.sql desde phpMyAdmin y copiar
servidor a htdocs\taller_android. Crear allí config.local.php si se necesitan
credenciales distintas, con este formato:
  <?php return ['user'=>'tu_usuario', 'password'=>'tu_clave', 'port'=>3306];

CONECTAR ANDROID
En la pantalla inicial, pulsar Configurar servidor:
- Emulador oficial de Android Studio:
  http://10.0.2.2/taller_android/operacion.php
- Emulador de terceros conectado por ADB o teléfono USB:
  adb reverse tcp:8080 tcp:80
  Configurar en la app: http://127.0.0.1:8080/taller_android/operacion.php
- Teléfono por Wi-Fi: usar la IP local del PC, con ambos en la misma red.
  Ejemplo de formato: http://IP_DEL_PC/taller_android/operacion.php
  La IP concreta depende de tu red y Apache debe aceptar la conexión.
La dirección debe terminar en operacion.php. Abrirla en el navegador devuelve
"Usa una petición POST"; eso es normal, la app usa POST.

PRUEBA PASO A PASO PARA LA ENTREGA
1. Iniciar servidor, abrir app y configurar la dirección.
2. Escribir correo, contraseña de 6 caracteres o más y nombre. Crear mi cuenta.
3. Abrir Administrar universidades, escribir nombre y web; Guardar nueva.
4. Anotar el ID asignado. Limpiar y buscar ese ID. Deben volver los mismos datos.
5. Cambiar el nombre y pulsar Modificar seleccionada. Comprobar el listado.
6. Eliminar seleccionada y confirmar. Buscar el ID: debe indicar que no existe.
7. Crear otra universidad, cerrar y abrir la app, iniciar sesión y verificar que
   sigue en el listado.
8. Abrir Usuarios y mi perfil. Cambiar nombre y guardar. Actualizar listado.
9. Cerrar sesión y volver a entrar. Probar también una contraseña incorrecta.
10. Crear una cuenta de prueba distinta y probar Eliminar mi cuenta.
Las capturas para entregar deben mostrar tu ejecución real de estas operaciones.

DECISIONES RESPECTO A LOS EJEMPLOS DE LAS GUÍAS
Se usa HttpURLConnection y org.json del SDK en lugar de los JAR antiguos.
Las peticiones van en un ExecutorService y las respuestas vuelven al hilo de UI.
Las contraseñas se guardan con hash, las consultas usan parámetros y el servidor
valida la sesión. Cada usuario puede editar/eliminar su propia cuenta, y todos
los autenticados pueden ver el directorio. El registro permite entrar por primera
vez sin necesitar una cuenta preexistente. El servicio y la app comparten este
contrato JSON adaptado; no mezclar con el PHP antiguo de la guía.
HTTP sin cifrar se habilita solo en la variante debug para la práctica local.
La sesión dura hasta 8 horas en el servidor y vive en memoria en Android.
Para publicar se requiere HTTPS, configuración propia de servidor y controles
adicionales de despliegue. Este proyecto se entrega para el taller local.
